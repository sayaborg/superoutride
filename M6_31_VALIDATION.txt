SUPER OUTRIDE M6.31 VALIDATION

Milestone: Reusable Raster Successor Chain Authoring
Package: super-outride-m6-31@0.6.31

Purpose:
- generalize M6.30 terminal promotion + next-successor wiring into an arbitrary-length linear chain compiler
- preserve M6.29 Raster successor factory as structural geometry authority
- derive stage rows, physical transition gates, physical handoff seams and final FINISH without duplicating chainage authoring
- keep stage environment/runtime creation outside the chain compiler through an explicit callback
- keep renderer, browser loop and vehicle physics unchanged

Primary primitive:
compileRasterSuccessorChain(source)

Input authority:
- sourceStageId
- sourceRuntime
- sourceStructural
- ordered successor steps
- finishGateId
- gate halfWidth
- createRuntime callback

Each successor step declares:
- stageId
- packageId
- choiceId
- gateId
- handoffId
- RasterSuccessorAuthoring

Derived output:
- source stage row
- generated stage rows
- transition rows
- handoff geometry rows embedded in declarative transitions
- final finish row
- structural successor list
- runtime list

Stage-kind rule:
- source stage = STAGE
- every generated stage except last = STAGE
- final generated stage = TERMINAL
- empty chains rejected

Geometry derivation:
For each generated successor:
- physical transition gate = source GuideChart at successor.sourceTransitionS
- physical handoff seam = source GuideChart at successor.sourceSeamS
- final FINISH = final generated GuideChart at final successor.finishS

Important correction found by initial CI:
- first implementation imported a nonexistent RasterStageSuccessorAuthoring type
- actual authority type is RasterSuccessorAuthoring
- StageContinuationLink.sourceFrame is intentionally a generic GuideCoordinateSource, not guaranteed GuideChart
- chain compiler now captures the concrete source GuideChart before generating each successor and derives physical gate/seam geometry from that chart
- this is both type-correct and semantically correct because the transition/seam physically belongs to the stage being left

Environment ownership:
createRuntime(structural, packageId, stageId, stepIndex)
- caller compiles ordinary runtime content
- returned packageId must equal authored packageId
- returned coordinateFrame must be exactly generated structural.chart
- mismatch rejected before declarative Route DAG compilation

Opaque repackaging:
repackageGuideChartRuntime(runtime, packageId)
- changes only package identity
- preserves coordinateFrame, roadView, SurfaceMap, GroundMap and all other runtime content references
- performs no coordinate or world-state transform
