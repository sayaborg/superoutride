## 1. 決定の要旨

タイヤごとに独立に較正する値は、縦横の容量係数muX/muYと、縦横の荷重当たり初期剛性kX/kYの4つ。既存の共通C1飽和関数を一つだけ使う。新しいタイヤ動的stateを持たない。

ポストピークの摩擦落差S、P→2P規則、その幅・負勾配の追加調整、drift/gripモードは廃止候補。スリップから同時に一組のFx/Fyを求める。縦横を別々に独立クリップしない。TCSはタイヤではなく、駆動トルクの所有層へ分離する。

『楕円にすれば現実的』『横容量は必ず縦容量の4倍』『四特性なら必ず全車種でドリフトできる』とは主張しない。円はmuX=muYの同じ式。強い異方性は、測定タイヤではなくゲーム較正として明示し、制動・通常走行・出力も同じ条件で検証する。

## 2. 観測からの根拠

- M9.18のC=kNは、荷重増加で正規化曲線上の位置を変えない。これを残す。
- ブレーキなしのアクセル進入は現行でも存在した。探索失敗を不存在の証明としない。
- P→2Pの負勾配を局所的に除く比較では、中間角の局所増幅率が正から負へ変わった。
- 幅を広げるだけでは、以前は滑走台地にあった釣合いを負勾配帯へ移す場合があった。
- 落差なしの単調な摩擦楕円で、通常入力から150/200 km/hの15→25→15度を確認した。
- 楕円だけでも大角度の操作感度は残った。スリップ・トルク負帰還と入力幅の較正で、短い操作誤差への応答が改善した。
- 縦剛性の変更は、同じ釣合いの力を保ちながら必要な縦滑り・車輪供給出力を変える。容量と剛性は別の特性である。

これらは過去の隔離研究の結果であり、今回この一般化設計の車体試験を新たに完了したという意味ではない。

## 3. パラメータとauthority

| 量 | 意味 | 制約 |
|---|---|---|
| muX | 基準路面での縦力容量/接地荷重 | 有限、正 |
| muY | 基準路面での横力容量/接地荷重 | 有限、正 |
| kX | 縦スリップに対する小スリップ剛性/接地荷重 | 有限、正 |
| kY | 横スリップに対する小スリップ剛性/接地荷重 | 有限、正 |

これらは本設計の無次元スリップに対する正規化係数。実際の剛性Cx=kX*N、Cy=kY*Nは導出値であり、別に保存しない。muX/muYの大小関係を強制しない。共通値kX=kYも同じ式の有効な較正であり、特殊モードではない。

既存の低速正則化速度v0と共通飽和関数Hは、別の共通契約として引き継ぐ。4という数は全システムの定数が4つという意味ではなく、独立したタイヤ較正値の数である。

compilerの出力または車両所有の実効タイヤ設定を唯一の力計算入力とし、実効値と旧倍率とUI表示値の重複したauthorityを作らない。プロフィールからの初期化と実行時の較正変更は役割を分け、力計算は解決済みの実効値だけを読む。前後・車種・駆動方式・コース・デバイス・車体betaによるタイヤ則の分岐を禁止する。

## 4. 構成則

### 4.1 入力

現在の接地点での縦速度Vx、横速度Vy、法線荷重N、車輪回転Omega、有効半径R、路面gripFactor m、上記4係数を読む。車体CGのbetaをタイヤslipとして代用しない。

既存の符号と正則化を残す。

```text
Vref = sqrt(Vx*Vx + v0*v0)
sx = (R*Omega - Vx) / Vref
sy = -Vy / Vref
```

タイヤ・TCS・診断は同じslip導出関数を使う。新しいslipの動的記憶や別の低速分母を作らない。

### 4.2 一つの需要と一つの飽和

有効な接触がなくN=0、または路面容量m=0ならFx=Fy=0とする。非有限・不正パラメータは検査で拒否する。容量が小さいからといって荷重や摩擦に最低値を足さない。

N>0、m>0では、

```text
Dx = N*kX*sx
Dy = N*kY*sy
Bx = m*muX*N
By = m*muY*N
rho = hypot(Dx/Bx, Dy/By)
lambda = H(rho)/rho     (rho=0なら連続極限lambda=1)
Fx = lambda*Dx
Fy = lambda*Dy
```

Nはrhoの式から代数的に消せる。実装上は、単位荷重当たり需要dX=kX*sx、dY=kY*syでrhoを計算し、最後にNを掛ければ、微小荷重の除算を避けられる。結果の物理的意味は同じ。

### 4.3 共通H

現行`radialC1Magnitude`を保持する。a=0.74、b=2-a=1.26を共通の既存較正とし、新しいタイヤごとの形状ノブを追加しない。

```text
H(rho) = rho                                      (0 <= rho <= a)
       = rho - (rho-a)^2 / [4*(1-a)]               (a < rho < 2-a)
       = 1                                        (rho >= 2-a)
```

中段は現行のHermite式を代数的に簡約した表現であり、新しい飽和形状ではない。実装の初段階では既存関数をそのまま再利用してもよい。a=0.74は自然定数ではない。既存比較との連続性を保つための共有形状値であり、後日変更する場合は独立の検証対象にする。

HはC1、非減少、0<=H<=1、H(rho)<=rho。H/rhoは非増加。純縦・純横で摩擦力をピーク後に落とす区間を持たない。

## 5. 純特性の意味

基準路面m=1では、

```text
純縦の容量到達slip = b*muX/kX
純横の容量到達slip = b*muY/kY
```

Pは別の独立stateではない。横の角度表示は、十分な前進速度の純横条件でatan(横slip)と読めるだけで、車体ドリフト角を意味しない。

kX=kYを強制すると、容量到達slipの比もmuX/muYへ固定される。容量比と剛性比を別々に設定できることが、今回の4係数化の目的である。kX変更による消費出力の改善を、操作性改善と同一視しない。

比較用の既試作は、muX=.75、muY=3、kX=kY=47.25。純縦容量到達slip=.02、純横=.08となる。この値は再現の基点であり、製品推奨値・実タイヤの代表値ではない。

## 6. 数学的性質

### 容量

```text
(Fx/Bx)^2 + (Fy/By)^2 = H(rho)^2 <= 1
```

したがって摩擦楕円内。muX=muYなら真円。初期剛性が違うことと容量が楕円であることは別である。

### 散逸

接地面に対する滑り速度u=(Vx-R*Omega, Vy)とすると、

```text
F dot u = -N*lambda*Vref*(kX*sx^2 + kY*sy^2) <= 0
```

タイヤと車輪を合わせた滑り仕事は非正。駆動中の車体への正の仕事まで禁止するものではない。差は駆動系が車輪へ供給する仕事である。

kX!=kYでは力は需要ベクトルに平行だが、滑り速度と必ず平行になるわけではない。これは接地面の局所Coulomb摩擦を厳密に積分したモデルではなく、集約された現象論的force-slip近似である。容量内・散逸性だけで実タイヤとの一致を証明したことにはしない。

### 荷重比例

同じslip/路面/較正ではF(c*N)=c*F(N)。ゼロ荷重で力ゼロ。荷重で容量到達slipを移動させない。

路面mは容量へ掛け、初期剛性はそのままという現行の境界を残す。そのため路面mを変えると容量到達slipは変わる。荷重Nの変更との効果を混同しない。

### 車輪方程式の一意性

aX=Dx/Bx、aY=Dy/Byとすると、

```text
dFx/d(aX) = Bx*[H'(rho)*aX^2/rho^2 + H(rho)*aY^2/rho^3] >= 0
```

ゼロ需要での微分は線形極限。固定接地観測・固定駆動トルクではFx(Omega)は非減少。既存の非制動残差

```text
Rwheel(Omega) = Iw/dt*(Omega-OmegaOld) - Tdrive
             + R*Fx(Omega) + Trolling(Omega)
```

はIw/dt>0により厳密増加となり、既存の単調二分法とCoulombブレーキのゼロ回転解を保持できる。bracketのタイヤトルク上限はR*Bxを使う。旧fmax=単一mu*Nを意味変更せず残してはならない。

これは固定接地条件のスカラー解の性質であり、車体全体・TCS閉ループ・変速を含む全域安定の証明ではない。

## 7. なぜドリフトが起こるか

後輪駆動トルク→車輪回転→sx増加→共有容量の中でFxとFyの配分が変化→車体の回頭と横滑り、という既存の因果を使う。『betaが大きくなったからmuを下げる』分岐はない。

円も楕円も、飽和境界の縦力限界付近では横力の変化率が大きくなる。ポストピーク落差をなくしても、この幾何学的な結合と車体の動的不安定性は消えない。タイヤだけで手放し安定を保証しない。

## 8. TCSとの境界

TCSはタイヤの一部にしない。タイヤはペダル・目標beta・スリップ目標・TCSゲインを読まない。TCSはタイヤの係数やFx/Fyを書き換えず、実際の駆動トルクを要求値以下へ制限する。

最初の比較は、すでに効果を測定した単純な負帰還を基準にする。

```text
q = max(0, 1-max(0,sx)/sCut)
Tdelivered = q*Trequested
```

sCutは駆動制御側の独立した較正値。0.75は研究値であり自然定数・タイヤのピークslipではない。最大スリップを強制する状態クリップでもない。目標値やdeadbandを持たない負帰還も成立する。未検証の介入開始閾値・目標slip・積分器を『一般的なTCSらしさ』のために追加しない。

既試作では、前時刻の車輪状態から各substepでqを評価し、そのスカラー車輪solveの間はTdeliveredを定数にしている。まずこの方式を比較の基点とし、implicitな制御へ変更する場合は数値契約も再検証する。

動的な根拠はTestarossa/RWD。AWDの集約slip、共通エンジントルク低減と既存固定配分の関係、無接地・逆走・低速は別途の制御設計課題であり、加重平均が万能と見なさない。タイヤ則にはそれらの車種分岐を持ち込まない。

TCSの強さ、ENG、D/ACTはタイヤ較正に混ぜない。TCSはタイヤの容量・出力を増やさない。ABSも同様で、低いmuXによる最大制動力不足を消せない。

## 9. 採用しない追加要素

ポストピーク倍率Sと遷移幅、超楕円指数、ドリフト判定state、target beta、タイヤの記憶・温度・圧力・摩耗、camber thrust、aligning moment、荷重感度mu(N)、四輪化/roll追加、速度依存mu、制動時だけ高いmuX、タイヤID/車種/コース別の例外を、この提案には追加しない。

実タイヤでそれらが重要でないという主張ではない。今回のreduced modelで未反証の省略を維持し、症状対策を下位のタイヤ則へ積まないというscope決定である。特にBIKEの現実的なcamber/roll特性の再現は別の問題である。

ダウンフォースは追加するなら空力の力としてサスペンション荷重へ伝え、muの速度補正で偽装しない。出力変更は駆動系に置く。コース半径はコースに置く。フレーム/レンダラ/メートルとHUD速度は変えない。

## 10. 較正と受け入れ

4係数を持つことは、4つ全部を不必要に違う値へしなければならないことを意味しない。最初に成功候補を再現し、同じ数式でmuX=muY、kX=kYの制約を一つずつ戻し、どの自由度が製品要件に本当に必要かを比較する。特にTCSを併用した状態で強い容量異方性を緩められるかは未確認であり、できると約束しない。

『実車の代表値』と『ゲームとして採用する高グリップ/強い異方性』は資料上区別する。成功値muY3/muX.75、ENG4、D6、sCut.75を一括して製品デフォルトへ昇格させない。

評価は次の順に独立させる。

1. 構成則: 縦横純特性、shared capacity、符号対称、passivity、N=0、荷重比例、路面、車輪残差一意性。
2. 車両タイヤ単独: 全9プロフィールの通常加速、制動、旋回、reverse/低速/接地喪失と回復。係数をブレーキ時だけ変更しない。
3. 駆動制御対照: TCSなし、参照点で同じトルクの固定倍率、スリップ負帰還を比較。入力分解能のD変更は別軸とする。
4. 主ゲーム要件: 150/200 km/hの通常入力進入、15→25→15度、退出、数秒の進入過渡、1秒誤差、継続誤差、反復誤差、入力遅れ、踏み増し余力。250 km/hは別断面として追加。
5. 実コース: 指定曲率の区間で、退出速度、区間の前進距離、消費出力、修正余力を測る。無限平面の円周累積距離を飛距離としない。実タッチ/キーボードを確認する。

約200 km/h・25度の以前の候補は半径約204m、必要車輪供給出力約548kW、トルク低減後でもENG4・アクセル約95.6%を必要とした。これらの制約は新しい型名では消えない。容量・出力・コース半径・角度の全部を固定したまま、タイヤ関数だけで全要求を達成できるという提案ではない。

旧G/P/S回帰の数値を黙って緩和しない。旧構成則を廃止する正式なsupersessionを記述してから、維持すべき因果回帰と廃止する曲線仕様回帰を分ける。比較用の旧lawは研究側に残せるが、本番に旧新2モデルや互換stateを常設しない。
