## 1. 結論

グリップ定常円と深いドリフト定常円は、どちらも現行本番ソルバで成立した。同じ一定入力でも、初期状態によって浅い旋回と深いドリフトへ分かれる結果を120秒積分で確認した。一方、通常旋回からその維持状態へ入る操作は今回の短いブレーキ操作探索では成立しなかった。

したがって主な問題は「旋回・ドリフトを物理的に維持できない」ことではなく、「成立している維持状態へ、普通の運転状態から入り、速度を保ちながら修正・退出できる操作経路が十分に確認されていない」ことにある。ただしユーザーが実際に感じた飛距離不足の主因を、プレイ記録なしで一意に断定することはできない。

提示された指摘のうち、急なポストピーク低下、複数の旋回状態、変速による空転抑制、強い制動時の後輪ロックは根拠がある。しかし「中間解は全条件で存在しない」「キーボードでは原理的に不可能」「後輪ロックで横力がゼロ」「2速以上ではドリフトをパワー維持できない」といった一般化は採用できない。

提案されたポストピーク5P化、前軸基準操舵、路面速度基準変速も分離して比較した。いずれも現行と同じ入力で望ましい8〜20度の維持状態を自動的に得る修正ではなかった。前二者は既存の深いドリフトを失わせ、変速変更は維持角をさらに深くした。これは再較正後の可能性を否定する結果ではないが、三変更の一括採用を正当化する結果でもない。

## 3. 実験方法と判定範囲

M9.18回帰テストと同じ平坦fixtureを使用した。Guideは `(0,-10000)` → `(0,10000)`、左右5000mのASPHALT、height=0。車両はTestarossa、通常の `updateArcadeVehicle` と本番の12 substeps、dt=1/60秒を使用した。通常比較はD12/M60、G2/P20/S1、ENG1。入力は保持中のtouchに対応するDIRECTである。

初期状態を作った後、速度・yaw・wheel omega・荷重・gearを上書きして維持する処理はない。gearは通常の自動変速に任せた。擾乱試験だけは、事前に明示した一回の初期速度方向変更を与えている。診断コピー以外の本番モジュールは変更していない。

定常候補の判定は末尾5秒の幅で行った：betaの幅<0.3度、speedの幅<0.1m/s、yaw rateの幅<0.01rad/s、十分な末尾サンプルがあり例外なし。この有限時間判定は固有値による厳密な安定性証明ではない。「30秒で判定を満たさない」ことも、不安定性の証明ではない。

betaはCG速度の車体相対角、Pは無次元タイヤ横滑り量のピーク位置であり、同じ量ではない。定常時の半径は `R = speed / abs(yawRate)`。距離は軌跡長であり、始点と終点の直線距離ではない。

## 7. 擾乱と通常旋回からの進入

u=0.8/throttle=0.70の深い維持状態に対して初期速度方向を一度だけ変更し、45秒保持した。-5度、-1度、+1度の方向変更は約23.11度へ戻ったが、+5度、すなわち浅い側へ押した条件はグリップ側へ移った。吸引域は方向によって非対称であり、単に「±5度が両方駄目」とまとめるのも不正確である。

さらに通常のグリップ円（u=1/throttle=0.20を60秒）から、brake=0.5/0.75/1.0を0.1〜0.6秒、その後u=0.8/throttle=0.70という18通りの時間指定入力を試した。フィードバック制御や途中の状態リセットはない。今回の18条件はすべて浅い旋回側へ戻り、40秒内に深いドリフト保持へつながらなかった。これは当該操作列の失敗であり、あらゆる進入操作の不可能性を示すものではない。

結果：`results/perturbations.json`、`results/entry-pulses.json`。

### 診断変更の厳密な意味

- **tail5**：`lateralPostPeakScale`の遷移幅をpeakから4×peakへ変更。開始Pは同じ、プラトー終点が5Pになる。
- **front**：既存の`deriveContactObservation`をsteer=0で呼び、前軸接地点の縦横速度から基準角を算出。現行の低速regularizationを維持した。ユーザー提示の非regularized `atan2(Vlat+a*r,Vlon)`そのものではない。現行の唯一のrackとM/D上限は維持。
- **roadshift**：既存の駆動配分で重み付けした接地点の路面縦速度/Rを変速判定にだけ使用。Testarossaでは後軸が対象。実RPM、トルク曲線、rev limiterは駆動輪omegaのまま。CGの速度絶対値を使ったわけではない。

前軸基準にすれば新しいstateは不要だが、現行101で明示的に除いたyaw rate依存が幾何学経由で操舵目標へ戻る。単なる誤記修正として扱わず、操舵契約の更新が必要である。路面速度基準の変速も現行111の「wheelspin時も同一の実RPM判定」という決定を更新する。

結果：`results/ab-*.json`。正確な診断差分：`diagnostic-diffs/*.diff`。全差分について本番全回帰テストを通したとは主張しない。

## 9. 各因果の検算と、過剰な一般化の修正

### 9.1 ポストピーク

P=0.20ではpure lateralのピーク角はatan(0.20)=約11.31度、2Pはatan(0.40)=約21.80度。G2/S1ならこの約10.49度で係数が2から1へ落ちる。平均勾配は約-0.0953/度であり、「急な低下」という指摘は妥当。

ただし、負のタイヤ勾配だけから、車両全体系の全平衡の安定性を断定することはできない。前後配分、操舵幾何、combined slip、エンジン、gear、速度の結合がある。実車の勾配を一律-0.01/度、あるいはG=0.9〜1.6を全条件で唯一正しい値とする根拠は、今回確認したrepositoryにはない。ここでは採用しない。

### 9.2 駆動力とグリップ

repositoryのTestarossa値から、後輪静荷重は9,561.48N、G2の静的容量は19,122.97N。470Nmのピークトルク、比、効率、後輪半径から、1速最大駆動力13,341.19N、2速8,557.67Nとなり、提示された概算は一致する。

しかしこれは直進・静荷重との比較であり、旋回時のcombined-slip容量と同一ではない。現にG2・ENG1・2速で約23度のドリフト維持を再現している。「直進で2速の駆動だけでは静的ピーク容量を超えない」と「旋回中にパワードリフトを維持できない」は区別する。

ENG3で0→100km/hが1.5秒という個別主張は、今回その加速試験を独立に再現していない。実測済みのようには扱わない。

### 9.3 自動変速

G1/S1、初速5m/s、直進フルスロットルでは、未変更モデルの1→2速変速が1.9333秒に発生した。変速直前の出力drive torque約3952.7Nmから直後約2739.0Nmへ低下し、rear sxも約0.178から0.136へ低下した。駆動力を弱め空転を抑える作用はある。

ただしこのケースでは空転開始後0.1秒以内の変速ではない。比だけの低下率と、RPM変化によるエンジントルクを含む実出力の低下率も同じではない。明示的なTCSやslip目標制御が実装されているわけではなく、変速結果が空転を抑制している。

路面速度基準へ変えても直進加速が必ず1速リミッターに閉じ込められるわけではない。G1/G2/G3の直進60秒比較では、未変更・路面速度基準とも5速まで到達した。この副作用を根拠なく主張しない。

結果：`results/ab-baseline.json`、`results/ab-roadshift.json`、`results/straight-shift-regression.json`。

### 9.4 ブレーキ

通常のグリップ円から100%ブレーキ、steering保持を行うと、約14.48m/sから1秒後2.35m/sへ落ち、betaは約-93.5度になった。0.25秒で後輪ロックを観測した。しかしロック時の後輪横力は約1,326Nで、ゼロではない。

現行one-kはFx/Fyを共通の滑りベクトル方向へ配分する。omega=0でもVyが非ゼロならFyがゼロになる一般則はない。ロックによるcombined-slip配分と動的荷重の変化が大きなヨー応答を作るのであって、「ロック検出でFyをゼロ化する」実装ではない。

同じグリップ円から15%と30%のブレーキでは、2秒の観測中に後輪ロックは起こらなかった。したがって「ブレーキ=必ずスピン」ではなく、特に強い制動・荷重移動時の問題である。ABS/TCS検討を待つ場合でも、ブレーキ試験を成功扱いから単に除外して欠陥を隠すべきではない。

結果：`results/brake-probes.json`。

### 9.5 操舵基準

平坦路・小角近似では、前軸の横速度はCG横速度にa*rを加えたものになる。CG基準の操舵目標から見た前輪横滑り量は、おおよそuDからその分だけ小さくなる。今回のグリップ円ではa*r/Vの角度相当が約5.55度で、指摘の規模は妥当である。

しかしこの項は単なる権限の「浪費」ではなく、yaw rateが増すと前輪の横滑りと横力が変化する現行の幾何的作用でもある。これを相殺すると旋回特性が大きく変わることをA/Bで確認した。Dが厳密に常に実タイヤslip angleになるという主張も、rack応答、飽和、低速regularization、接地点の姿勢・路面を考慮すると成立範囲の明示が必要。

### 9.6 Touchとkeyboard

touchの全幅64 CSS pxに対してthrottle差0.05は3.2 CSS pxに相当する。状態の分岐がこの差で起きれば操作は難しくなる。

一方、保持中のtouchはDIRECTであり、ACT=0.25秒の入力apply遅れを通らない。ACTの数字をそのまま人間の制御帯域とすることはできない。物理rackの有限応答は別に残る。

keyboardでは部分入力を押しっぱなしで正確に保つことはできないが、既存の有限actuatorと短い押下・解放で中間量を作る経路があり、repositoryの回帰にもデジタルthrottle連打で中間量を維持する試験がある。「原理的に不可能」は過剰。実用的な人間操作として十分な幅・時間余裕があるかは別の未証明事項である。

## 10. 飛距離についての判定

現行法則には「一定距離でドリフトを終える」制御は見つからず、M9.18の30秒・450m保持、G2/ENG1の120秒保持が成立した。少なくとも、この条件での飛距離不足をタイヤが必ず短時間で速度を奪い切るためとする説明は成立しない。

他方、定常枝に入っていない進入・角度修正・強い制動では速度を大きく失う。実際の体感については、滑り角だけでなく速度、走行距離、前後のFx/Fy、荷重、wheel sx/sy、gear/RPMを同じ操作記録で確認する必要がある。今回の診断はユーザーの実プレイ操作を記録・再生したものではない。

Sを上げれば同じ滑り状態で摩擦合力が増え得るし、5P化も旧2P近傍の力を増やす。したがって「低下を緩めれば飛距離も必ず延びる」とは限らない。今回は実際に同じ保持入力からドリフトを失う比較結果が得られた。

描画については大きなyawで知覚しにくくなる問題がhandoffにも記録されている。しかし物理円の存在だけで描画が唯一の原因とは言えない。rendererを今回実走検証したわけではなく、Coreのchainage depthを変更する修正も行っていない。

## 11. 次の変更に対する判断

最も確実に採用できるのは、**本番ソルバを使った維持・進入・擾乱の診断を固定化すること**。単なる「8秒後のbeta格子」ではなく、初期値別、gear別、速度変化と末尾変動幅を持つものにする。

以後の候補は一原因ずつ比較する。変速の路面速度基準案は、実RPM/limiterを保持できる状態追加不要の候補だが、角度が深くなるだけの結果を操縦性改善と誤認しない。前軸基準案は操舵の新契約として扱い、等価な前輪slip/力を揃えたD再較正と、低速・逆向き・路面姿勢・上限制約を確認する。タイヤの遷移幅とS/Gは、速度収支と進入可能性を含む限定された目標運用域で評価し、5Pや0.75を先に正解として固定しない。

受け入れ条件の候補は、同一の目標速度域で浅い旋回→8〜20度→深いドリフト→退出が通常入力だけでつながること、速度を同時に保持できること、+/-擾乱に対する余裕、DIRECT touchとrate-limited keyboardの双方で実際の入力列を評価すること。全入力領域に一つの単調関数beta(u,th)が存在することを無条件に要求するのではなく、遊びに必要な運用域とgearを明示する。

正式変更を行う際はAGENTSのArchitecture Decision Gate、番号付きscoped authority、既存因果テスト、全車種回帰、exact-head CI、必要なvalidation recordとその包含CI、pure fast-forward、same-SHA Pagesを満たす。今回の診断結果だけでM9.19のrelease完了や操縦性の完成を宣言しない。
