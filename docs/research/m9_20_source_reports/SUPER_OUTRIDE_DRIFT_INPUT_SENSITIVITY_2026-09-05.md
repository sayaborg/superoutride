# SUPER OUTRIDE — 高速ドリフトの入力感度と駆動制御・続報

2026-09-05 / 隔離された研究。**未実装・未リリースの候補であり、repositoryの現行権威ではない。**

## 1. 今回の結論

前回の単調な摩擦楕円（横容量3、縦容量0.75、横ピーク8%、ポストピーク落差なし）を比較の基点にした。

1. タイヤ容量境界の形と縦容量を変えるだけでも、200 km/h・25°での入力誤差応答を小さくできる。しかし今回の離散的比較では、1秒間の±0.02入力誤差による最大角度差は約9.10°から、良い例でも約4.86°だった。
2. 同じ楕円タイヤに、縦スリップ増加に応じて駆動トルクを減らすフィードバックを加えると、同じ種類の誤差試験で約3.12°となった。
3. さらに既存のDriver舵角幅Dを12°から6°にして、同じ物理舵角をより広い正規化入力範囲で使うと、200 km/h・60 Hzでは約1.94°へ下がった。150/200 km/h、左右、60/120/240 Hzの108誤差ケースを完了し、最大約2.001°だった。「厳密に2°以下」とはしていない。
4. 同時に、通常の前進状態から150/200 km/hの15→25→15°を行う12ケース、舵一定・ブレーキなしで3秒のアクセル踏み増しから200 km/h・25°へ到達する6ケースを確認した。
5. 急なアクセル踏み増しでは最大約38.7°の行き過ぎが残る。誤差耐性が改善しても、あらゆる進入操作が容易になったわけではない。

したがって、現段階ではタイヤ則をさらに複雑にすることよりも、**成立するタイヤ則と、駆動トルクのフィードバック、入力分解能を役割分担させる構成**を比較の中心にする根拠がある。これは静的トルクキャップではなく、TCSに近いスリップ・フィードバックである。

## 3. 実験の分離

### タイヤ構成則だけの変更

次のノルムを使って、既存のradial C1飽和の尺度を変更した。

```
Dx = Kx N sx
Dy = Ky N sy
rho = ( |Dx/eta|^p + |Dy|^p )^(1/p) / (muY N)
F = (Dx,Dy) * H(rho)/rho
eta = muX/muY
```

p=2が摩擦楕円。p=1.5/1.25は、より菱形に近い容量境界の比較であり、標準的な摩擦楕円と同一とは呼ばない。ポストピーク倍率は全てS/G=1で無効。p>=1でノルムは凸であり、両成分への共通非負倍率による散逸は維持する。

16タイヤモデルについて、150/200 km/h × β=2/4/10/15/20/25/30°を計算。**224回の釣合い探索は全て収束、うち197点が検討した舵範囲とENG<=4を満たした。** これは根の探索であり、通常入力からの到達証拠ではない。`equilibria.json`の追加56行は4つの駆動比較の係数から導いた同一釣合いで、独立した新たな根探索として数えない。

`scan.py`の再実行用出力は `equilibria-tire-rerun.json`。記録済みの入力値を意図せず上書きしない。

### 普通の入力で到達させる比較

人工的な横滑り姿勢を与えず、初期速度150/200 km/h、横速度0、yaw rate0、rack0から始める。ブレーキなし。入力は事前に釣合いから計算し丸めた値を時間に沿って渡す。β観測を用いて入力を修正しない。

一定なのは「外部から与える入力列」であり、既存の進行方向自動舵と、候補のスリップによるトルク低減は動く。新しい候補を「フィードバックなし」と表現しない。

## 4. タイヤ単独の結果

200 km/h・25°の連続釣合いの例。前後タイヤは同一法則。各モデルごとに入力を合わせ直している。

| モデル | μx/μy | 容量境界p | 軌跡半径m | 後輪 dFy/dFx | 車輪供給出力kW |
|---|---:|---:|---:|---:|---:|
| E25（前回の候補） | 0.25 | 2 | 203.85 | -10.04 | 548.17 |
| E30 | 0.30 | 2 | 169.94 | -6.97 | 658.89 |
| N15_X30 | 0.30 | 1.5 | 187.72 | -4.81 | 591.54 |
| N125_X35 | 0.35 | 1.25 | 181.19 | -3.30 | 612.65 |

dFy/dFxは飽和境界上・固定荷重での局所微分。車体全体のアクセル−βゲインとは同一ではない。

1秒間の入力誤差の最大角度差は、E25=9.097°、E30=4.943°、N15_X30=6.078°、N125_X35=4.865°。力配分の微分だけで、車体の操作感度は決まらない。半径・出力も変わるので、全部を同等のゲーム挙動として比較しない。

縦剛性を2倍/4倍にすると、同じ200 km/h・25°の釣合いで後輪sxは0.296→0.148→0.074、供給出力は548→486→454 kWへ減る。しかしタイヤの合力値、軌跡半径、dFy/dFxは同じ。縦スリップ損失は減らせても、力配分の静的な過敏さはそのまま。今回の時間入力列ではKx2/4が同じ往復に捕捉されない例もある。これを全てのKx変更の不可能証明とはしない。

証拠: `equilibria.json`, `scan.log`, `cycle-*.json`, `margins-*.json`。

## 5. 駆動トルクのスリップ・フィードバック

本命の比較には、新しい容量境界pを追加せず、元のE25を使った。

```
muY=3.00, muX=0.75, Py=0.08, Kx=Ky=47.25
postpeak drop=0
```

車輪回転数と接地点速度から、既存の正則化を用いた駆動輪の縦スリップを計算する。Testarossaでは後輪sxそのもの。複数駆動軸用のコードは既存の固定トルク配分で加重するが、今回の動的検証はTestarossaのみであり、AWD等での有効性は未検証。

```
sx = (R Omega - Vx) / hypot(Vx, v0)
q = max(0, 1 - max(0,sx)/0.75)
T_delivered = T_requested * q
```

T_requestedは現行のエンジン曲線、ENG倍率、実車輪RPMによる変速、効率、リミッター、アクセルを通した要求トルク。候補はその後で低減し、既存の車輪方程式へ渡す。制動トルクは変更しない。

これは**スリップ・フィードバック / TCSに近い制御**であり、固定トルク上限ではない。sx=0.75はこの試作で駆動がゼロになる位置で、実際の車輪速度を強制的に上書きする上限ではない。タイヤ力、車輪Ω、車体速度、β、ヨーレートを直接修正しない。新しい積分器や制御メモリは持たず、既存の車輪状態を読む。

例: sx=0.30ならq=0.60。sxが増せば駆動を減らし、減れば同じアクセルでも駆動が戻る。ゼロスリップを強制しない。

200 km/h・25°の連続釣合いでは、後輪sx=0.29605、q=0.60527、後輪縦容量使用率=92.90%、半径203.85m、供給出力548.17kW。**タイヤの余力を増やしたり、必要出力を消したりしたわけではない。** 変わったのはずれへの応答である。

この低減後にも同じトルクを供給するため、必要ENG最小値は2.314から3.824へ上がる。比較ではENG4を使用。200 km/h・25°のアクセルは約0.956で、さらに踏み増す余裕は約4.4ポイントしかない。元のENG3で同じ能力を無償で残したとは言えない。

`powertrain.outputDriveTorque`は要求値、`control.deliveredDriveTorque`は実際の低減後の値。観測コードは二つを分け、供給出力には後者を使用した。

## 6. 固定倍率との比較: フィードバックを分離

参照する25°の釣合いでq=0.60527を固定した別モデルを作った。ENG4のまま、各維持点の入力を合わせ直す。一定の倍率を掛けるだけなら、同じ基準点の力は合わせられるが、dq/dsxがない。

|---|---:|---:|
| 元の楕円・ENG3 | 12° | 9.097° |
| 固定q・ENG4 | 12° | 7.945° |
| スリップ依存q・ENG4 | 12° | 3.119° |

| 固定q・ENG4 | 6° | 6.264° |

固定倍率対照は連続釣合いの基準点で倍率を一致させたもの。全時系列がバイト単位で同じ初期状態になる比較ではない。各実行で到達した25°状態を分岐し、その構成自身の無誤差時系列との差を評価する。

タイヤも舵幅も同じD6の条件で、固定倍率6.264°に対しフィードバック1.935°。単にエンジン倍率を下げたから鈍感になった、という説明だけでは、この差を説明できない。

## 7. D6は新しい操舵則ではなく、入力範囲の使い方

Dはプレイヤー入力で追加する舵角の最大値。ラック上限M=60°は変更しない。現在のブラウザはD10〜20°なので、**D6は現行選択範囲外の研究値**。

同じ物理的なDriver舵角を出すために、既存の uD を保って u を2倍にする。

```
D12: u=0.260 -> driver offset 3.12°
D6:  u=0.520 -> driver offset 3.12°
```

この範囲で同じ舵角を入力のより広い部分へ割り当てる。その結果、同じ±0.02の入力誤差が作る物理舵角誤差は±0.24°から±0.12°になる。魔法のヨー安定化ではない。

既存A=M-Dの自動舵上限も変わるが、ここでの nominal ドリフトは両方の上限内。解放前の同じ物理舵角の時間列は維持できる。正規化actuatorからの解放時間は変わり得るため、中立退出は実際に再検証した。ACTのrateは変更していない。

小さいDでは一般の低速・狭半径走行の操作権限が不足する可能性がある。今回の高速操作列では足りたが、全走行を保証しない。デバイス別物理分岐や速度別のD切替は追加していない。

## 9. 短い誤差と持続誤差

各往復の30秒時点まで通常入力で到達した状態を独立コピーする。25°維持入力を続ける無誤差対照と比較し、u,THそれぞれ-0.02/0/+0.02の9組を1秒だけ加え、元に戻して20秒観測。すべての極値を毎tickで比較し、保存時系列は10 Hzへ間引く。

**12構成条件×9組=108ケース（無誤差組を含む）を完了。**

| 速度 | 60 Hz最大角度差 | 120 Hz | 240 Hz |
|---|---:|---:|---:|
| 150 km/h | 1.990° | 1.997° | 2.001° |
| 200 km/h | 1.935° | 1.944° | 1.948° |

左右同じ範囲。lock/lift/error=0。速度差の最大は全ケースで約1.41 km/h未満、20秒時点の角度差は0.008°未満。これは外部からβを指定した保持制御ではない。

連続値の誤差領域全体、反復する誤操作、遅れを含む人間の操作は証明していない。最初の長いバッチが実行時間制限で途中停止したが、完了済み結果を保持して残りを別実行し、最終12構成が揃ったことをassertした。

別途、**200 km/h・60 Hz・正方向のみ**で誤差を20秒保持する9組も確認。末尾5秒の平均角度は23.92–26.00°、平均速度189.07–211.65 km/h。滑りは残るが、同じ速度を保ったわけではない。この持続誤差の9組を108ケース全ての証拠と混同しない。

## 11. 数値・構造チェックと限界

主候補のタイヤについて50,652サンプルを再検査。容量楕円の二乗和最大1.0000000000000004（丸め誤差）、正の滑り仕事0、N=0で力0、N倍で力比例、固定横滑りでFxが非減少。タイヤ／車輪残差自体は前回の単調な楕円と同じ。追加のトルクは旧車輪状態で評価し、そのsubstepのimplicit wheel solveでは定数として渡される。閉ループ全域の安定性は別問題であり、時間刻み比較を併用した。

135ファイル・32,460保存サンプルで、実際に車輪へ渡したトルクが要求トルク以下かつ非負であることを確認。βや速度への直接補正はない。新制御状態なし。ただし低速・逆走・空中・片輪接触・全9車種の閉ループ挙動やsource boundary全体の製品テストは未実施。

候補は縦横容量比4:1という強いゲーム向け異方性を保っている。縦容量が低いことによる制動の弱さは未解決。前回の楕円の制動結果を今回新たに改善したとは言わない。200 km/h・25°で約548 kW、半径約204mという力・エネルギー予算も変わらない。実コースでの有用な前進距離を、円運動の累積距離で代用しない。

D6の全域適合性、95.6%アクセルという高い維持入力、実機タッチの解像度とキーボードのデジタル入力、人間の反応遅れ、より広い速度域／250 km/h、誤差の反復等も未検証。

## 12. 設計判断

今回の証拠は「新しいタイヤ単独で全て解く」方向よりも、役割分担を支持する。

- タイヤ構成則は高速ドリフトが到達可能な力配分を提供する。
- 駆動制御は車輪空転の増大に対する過敏さを抑える。
- 入力較正は必要な操舵幅を人間が使える入力の範囲へ割り当てる。

ここでの制御は車体の横滑り角を目標へ吸着させない。滑走を残すため、通常の「滑らないタイヤへ戻す」一択の制御でもない。前段の試験でTCSを常に後回しにした判断を、今回の反証比較に基づいて改める根拠がある。

採用を決める前に、低速の旋回・制動、駆動レイアウト別挙動、実コースの数秒間の滑走、実入力、急踏み・反復誤差を確認すべき。D6や0.75を新しい普遍定数として固定する段階ではない。実装するなら、権威文書・型・コンパイラ・回帰を更新する必要がある。
