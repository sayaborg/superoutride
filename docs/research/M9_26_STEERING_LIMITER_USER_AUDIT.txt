リポジトリ（`sayaborg/superoutride`）を clone して、`src/physics/tire-wheel.ts`、`tire-friction-calibration.ts`、`vehicle-dynamics.ts`、`arcade-vehicle-physics.ts`、`vehicle/production-vehicle-profiles.ts`、および `docs/80_m8_1`・`docs/101_m9_11`・`docs/research/M9_25_STEERING_STOPPER_ASSESSMENT.md` を照合しました。数式は実装から再導出し、現行パラメータで数値検証もしています。

## 総評

**数学は正しい。前提と結論の位置づけが間違っている。**

§2〜§6 の導出は、記号の対応を含めて現行実装と完全に一致し、私が独立に再導出した結果とも一致しました。しかし、この文書が「不要だ」と論じている「速度別の制限表」はリポジトリに存在しません。現行は M9.11 の travel-direction steering であり、争点は「表を使うか式を使うか」ではなく「**定数 D（`steeringOffsetMax`）を状態依存にすべきか**」です。そして現行パラメータで数値を入れると、この提案は「切りすぎを止めるストッパー」ではなく「制動中に切れ角を大幅に**許可する**もの」になります。

## 1. 実装との照合（正しい部分）

| 文書 | 実装 | 判定 |
|---|---|---|
| \(q=\sqrt{V^2\cos^2\alpha+v_0^2}\) | `tireReferenceSpeed = hypot(longitudinalVelocity, v0)` | ✓ |
| \(s_x,s_y\) | `slipAtReferenceSpeed` | ✓ |
| \(\rho=\sqrt{(k_xs_x/m\mu_x)^2+(k_ys_y/m\mu_y)^2}\) | `hypot(x,y)/gripFactor` | ✓ |
| \(H(\rho)\) 三区間 | `radialC1Magnitude` | ✓ 完全一致 |
| \((F_x,F_y)=\frac{H}{\rho}(D_x,D_y)\) | `capacityX*h*(x/length)` | ✓ 代数的に同値 |
| \(m\) = 路面相対摩擦 | `surface.material.gripFactor` | ✓ |

さらに、文書が明示していない**有利な事実**が2つあります。どちらも提案の成立を助けます。

- `reachVelocity` は `body.velocity + omega × freeOffset` で、`steerAngle` に依存しません。よって接地点の面内速度 \(V\) は \(\delta\) の関数ではなく、\(J(\alpha)\) の1変数化は厳密に正当です。
- `normalLoad` も `gap`/`qDot` 経由で `steerAngle` に依存しません。substep 内で \(N\) 固定は近似ではなく厳密です。

導出の検証結果：

- **§5 の \(\cos^2\alpha_{\rm lin}=v_0/(\sqrt{V^2+v_0^2}+v_0)\)** — 独立に微分して \(V^2X^2+2v_0^2X-v_0^2=0\) を得ました。有理化すると文書の式と恒等的に一致。✓
- **§6 の三次式 \(\rho^3+(2c^2-a^2)\rho-2(2-a)c^2=0\)** — \(H,H'\) を代入して展開、係数まで一致。✓

補足として、\(k_Y=(2-a)G_Y/P_Y\) かつ \(\mu_Y=G_Y\) なので

$$c=\frac{k_Y}{m\mu_Y}=\frac{2-a}{m\,P_Y}$$

となり、**\(c\) はグリップの大きさに依存せず、knee・路面 \(m\)・peak slip \(P_Y\) だけで決まります**。文書に入れる価値のある簡約です。

## 2. 現行パラメータでの実測（ここが問題）

`REFERENCE_TIRE` は \(G=1.35,\ P=1.26\times1.35/9.75=0.1745,\ a=0.74,\ v_0=1.0\)。よって \(c=7.2222\)。

**§6 の三次式の根**：\(\rho=1.24792\)（区間 \((0.74,\,1.26)\) の上端ぎりぎり）→ \(\alpha=9.803^\circ\)。数値最大化（V=40 m/s）で 9.8154° と一致。✓

**§5 の 45° がどこに存在するか**（純横滑り、数値最大化 vs 線形式予測）：

| \(V\) [m/s] | 数値の最適角 | §5 線形式 | 最適点での \(\rho\) |
|---|---|---|---|
| 0.05 | 45.02° | 45.02° | 0.255（線形域内 ✓）|
| 0.2 | 39.85° | 45.28° | 0.915（**飽和済み**）|
| 1.0 | 13.79° | 49.94° | 1.235 |
| 5.0 | 10.00° | 66.11° | 1.247 |
| 30 | 9.81° | 79.66° | 1.248 |

**§5 が記述している領域は、現行タイヤでは \(V\lesssim0.1\) m/s しか存在しません。** 文書は「線形域を外れていれば解き直せ」と正しく但し書きしていますが、結論部の「低速で大きな角度が有効になる性質も、同じ式から導出できる」という主張は、実質的に歩行速度未満のみを指すことになります。この点は本文で明示すべきです。

## 3. 重大な指摘

### 3.1 前提の齟齬 — 反論対象が存在しない

現行の操舵法則（`travelDirectionSteeringTarget`）は：

```
δ_target = clamp( clamp(β_travel, ±A) + u·D, ±M ),  A = M − D
```

`FERRARI_TESTAROSSA`: M=45°, D=9.5°, A=35.5°。速度テーブルはどこにもありません。**現行 D は、既にほぼ定数の「切りすぎストッパー」として機能しています。** そして偶然にも D=9.5° は §6 の高速漸近解 9.803° にきわめて近い。文書はこの一致に触れていませんが、これは提案の最大の傍証であると同時に「では何が改善されるのか」という問いを突きつけます。

### 3.2 \(\alpha\) と \(\beta\) は別の量

文書の \(\alpha\) は**前輪接地点**の進行方向基準です。現行法則の \(\beta\) は **CG** の進行方向（`vehicleBodyTravelDirection`）で、ヨー時には \(\phi_{\rm front}\approx\arctan\frac{v_{lat}+\ell_f\dot\psi}{v_{lon}}\ne\beta\)。したがって \(\alpha\) に上限を課しても、それは現行 D の上限ではありません。**§8 の clamp をそのまま実装すると、旋回中に運転者の実効操舵権限が非対称かつ不連続に動きます。** `docs/research/M9_25` は同じ指摘を既にしています（文書はこれを引用も反証もしていません）。

### 3.3 \(\delta\) → \(\alpha\) の写像が抜けている

`deriveContactObservation` では `wheelForward` を `body.up` 回りに \(\delta\) 回転させたあと**接地面へ射影**して `tireForward` を作ります。傾斜・バンク面では「面内の車輪方位」は \(\delta\) の非線形関数です。§8 の \(\operatorname{clamp}(\delta_{\rm request},\delta_-,\delta_+)\) を成立させるには、この射影の逆写像が要ります。§9-1 の「計算対象」として一括りにされていますが、これは目的関数の選択ではなく**座標の問題**なので、別項目として立てるべきです。`tireFrameValid=false` の分岐も未処理です。

### 3.4 退化条件が1つ足りない — ロック輪

§9-3 は「停止・無接地・摩擦ゼロ」を挙げますが、**\(\mu_x=\mu_y\) かつ完全飽和のとき、力は滑り速度と厳密に反平行になり、\(J(\alpha)\equiv0\) が全角度で成立します。** 現行 `REFERENCE_TIRE` は \(\mu_x=\mu_y=1.35\) なので、これは正確に起こります。数値確認済み（V=40, w=0 で全角度 0.00 kN）。

`solveWheelOmega` は `locked` フラグを持ち、ブレーキ全開でロックは実際に発生します。**走行中に、最適角が定義されない状態へ入ります。** これは停止時の退化より深刻です。

### 3.5 目的関数が制動中に破綻する — 「ストッパー」が「許可器」になる

\(\mu_x=\mu_y\) の飽和域では、\(J\) を厳密に解けます：

$$J(\alpha)=\frac{B\,w\sin\alpha}{\sqrt{w^2+V^2-2wV\cos\alpha}},\qquad \boxed{\cos\alpha^\*=\frac{w}{V}}$$

つまり**最適角は「前後滑りがゼロになる角」\(s_x=0\)** です。数値確認（V=40 m/s, N=4 kN）：

| 状態 | \(w/V\) | 最適角 | \(J_{\max}\) |
|---|---|---|---|
| 転がり | 1.00 | 9.85° | 5.38 kN |
| 制動 | 0.90 | 25.84° | 4.86 kN |
| 制動 | 0.70 | **45.57°** | 3.78 kN |
| ロック | 0 | 未定義 | 0 |
| 駆動 | 1.10 | 24.62° | 5.40 kN |
| 駆動 | 1.40 | **44.42°** | 5.40 kN |

`arccos(0.7)=45.573°`、`arccos(1/1.4)=44.415°` と厳密に一致します。

**これが致命的です。** 「瞬間旋回力最大化」を採用すると、有効操舵範囲は転がり時の 9.8° から制動時の 45.6°（＝機械限界 M=45° そのもの）まで **4.6 倍**に開きます。しかもその領域で得られる力自体は 5.38→3.78 kN に落ちています。ブレーキを踏むほどストッパーが緩む設計であり、「過剰に切りすぎないようにする」という当初の目的と正反対に作用します。§3 の「駆動中や制動中には結果が異なる」という注意書きは正しいのですが、**差の符号と大きさが致命的だという評価が抜けています。**

なお、飽和域の最適角が「\(s_x=0\)」であるということは、これは操舵の安全境界ではなく、単なる**前後スリップ最小化条件**です。これを「有効操舵限界」と呼ぶのは物理的に無理があります。

### 3.6 履歴との整合 — M8.0 の useful-steer cap は退役済み

`docs/80_m8_1_car_self_steering_control.md` §5 は、まさにこの種の機構を明示的に退役させています：

> M8.0 の useful-steer cap と front-utilization 比較は CAR について退役。新しい操舵法則の下に残してはならない。

この文書は、名前を変えた同じ機構の再導入提案です。**なぜ今回は違うのか**を明示的に書かない限り、リポジトリの design authority（root `AGENTS.md`）と衝突します。`usefulLateralCapacity()` が `tire-wheel.ts` に "diagnostic only" として残っているのも、その退役の痕跡です。

### 3.7 §4 の A/B — B は実時間で成立しない

Mode B は候補角ごとに `solveWheelOmega` を回します。現行は 60 fps × `VEHICLE_SUBSTEPS=12` = 720 回/秒（前輪）。候補角 20 点 × `bisectMonotone` 最大 60 反復とすると、フレームあたり ~14,400 回のタイヤ評価が操舵探索の内側に入ります。ラスタ描画と同居するブラウザ 60 fps では現実的ではありません。§4 の「AとBは同じ最適化問題ではない」という注意は正しく、B は事実上除外と書いてよいと思います。

### 3.8 連続性 — 仮定ではなく実測される跳び

§8 の「最適点が切り替わると目標角が跳ぶ可能性がある」は、上表のとおり**可能性ではなく確定事項**です。ブレーキ踏み込みで \(w/V\) が 1.0→0.7 に動く間に上限が 9.8°→45.6° へ滑らかに動くとしても、`steeringResponseTau=0.01s` のラックはそれに追随してしまい、`u` 一定でも実舵角が動きます。運転者の入力と無関係に舵角が変わる挙動は、M8.1 が禁じた assist-state の再導入と区別がつきにくくなります。

## 4. 評価できる点

- **目的関数を \(F_y\) ではなく \(J=F_x\sin\alpha+F_y\cos\alpha\) と定義したこと**は正しく、これまでのリポジトリ内文書より一段精密です。M9_25 は「travel-normal force = \(F_y\cos\alpha\)」までしか書いていません。
- **§4 の A/B 区別**と「差が小さいと仮定してはならない」という規律は良い。
- **§5 の 45° を「極限であって停止時の一意解ではない」と明記した点**は、M9_25 の「静止時に高速値を適用するな」と同じ結論に独立に到達しており、正しい。
- **単峰性を証明していないと自認している点**は誠実です。実際、私の走査では退化ケースを除き各符号側に極大が1つでしたが、これは証明ではありません。

## 5. 推奨

1. **タイトルと結論の主張を差し替える。** 「速度別制限表を使わない方法」ではなく「定数 D を状態依存の \(E(x)\) に置き換える提案」として書き直す。制限表は現行に存在しません。
2. **目的関数を \(J\) 最大化から外す。** 上の 3.5 が示すとおり、\(J\) 最大化は制動時に上限を機械限界まで開放します。「切りすぎを止める」が目的なら、目的関数は旋回力ではなく**前輪の飽和余裕**（`rho`、既に `frontUtilization` として HUD に出ています）か、rear との配分を含む量であるべきです。M9_25 の \(L\) を「別途正当化された定数」とした判断は、この意味で妥当でした。
3. **§9-3 にロック輪を追加**し、\(\mu_x=\mu_y\) で \(J\equiv0\) となる証明を本文に入れる。
4. **§8 に \(\delta\leftrightarrow\alpha\) の面内射影を明記**し、`tireFrameValid=false` と空中時の方針を書く。
5. **M8.1 §5 と M9_25 を明示的に参照**し、退役済み機構との差分を1節設ける。これがないと PR レビューを通らないはずです。
6. \(c=(2-a)/(m P_Y)\) の簡約と、飽和域の閉形式 \(\cos\alpha^\*=w/V\)（\(\mu_x=\mu_y\) 条件付き）を §6 に追加する。三次式より適用範囲が広く、しかも「これは安全境界ではない」ことを示す最良の材料です。

現状の提案は、`docs/research/` に「\(J\) 最大化は操舵ストッパーの目的関数として不適である」という否定的結論の研究ノートとして残すのが、いちばん価値が出る形だと思います。
