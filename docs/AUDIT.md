# Current design and vehicle-freeze audit

This checkpoint resolves the external audit of the inspected main (`979282e`) and reviews the repository as the sole project authority. All repository documentation is English. Architectural elegance, simplicity, one authority per concept and ordinary compiled data take priority over ad hoc exceptions.

## Scope and decisions

The starting inventory contained 332 tracked files. The review covered maintained source, types, compilers, tests, diagnostics, documents, configuration and release workflow. All maintained text was inspected through source review, syntax/format checks and dependency analysis; generated dependencies, builds and local logs are derived products. Particular attention went to vehicle equations, control ownership, source-domain boundaries, supported chart containment and browser actor lifecycles. This is an engineering audit with executable evidence, not a proof that every possible state is defect-free.

The architecture gate led to these decisions:

- Readers own their supported envelopes; compilation checks them where geometry and content meet. Keep strict containment and enlarge authored chart margins, without widening physical roads or adding a pose/force correction.
- Core owns finite-domain normalization, ordered immutable profiles and elementary validation. Domain-specific constraints remain with their owning compiler.
- Terrain traverses authored boundaries directly. A finite index or adjacent interval advances the traversal; no coordinate nudge is needed.
- The browser shell owns scheduling. Runtime composition owns each actor's physics/recovery/progress sequence; roots supply content and input policy.
- General APIs use role names and named arguments. Vehicle mechanics and their calibrated parameters remain unchanged.

### Supported chart decision

The enforced rule is `maxSupportedAbsL + abs(lateralOrigin) < guide.lMax`. Bounds include the actual classifier's boundary tolerance. Measuring only the first BRANCHING package misses translated second-fork support:

| Production content               | Guide limit, m | Greatest supported bound in the Guide basis, m |
| -------------------------------- | -------------: | ---------------------------------------------: |
| BRANCHING, every runtime package |             20 |                                   19.500000001 |
| LINEAR                           |             13 |                                             12 |
| TSUKUBA                          |             13 |                                             12 |
| FISCO                            |             18 |                                             17 |

Road/material widths are unchanged. Focused DEV content also receives valid chart margins. The audit additionally found that explicit lateral clamping used a translated local coordinate against unshifted Guide limits; it now clamps in the Guide basis first. Ordinary physics projection stays unclamped. The regression checks an offset chart and free world motion.

Two assertions in the external report needed qualification. Not all production courses pass through the authored-stage compiler, so every actual composition boundary is covered. Also, `lMax` is a chosen metric bound with positive Jacobian, not the singularity `J=0`; equality does not mean every current course actually attains its minimum Jacobian. Strict interior margin is the deliberate content contract.

Exact boundary deduplication is deliberate: tolerance-based merging would erase distinct authored intervals. No epsilon nudge or hidden wrapping replaces that data. These decisions are recorded in [architecture](architecture.md).

## Vehicle freeze and regression contract

The two-station contact model, unilateral spring/damper support, elliptical dissipative tire map, implicit signed wheel solve, direct gearing, torque protection, automatic steering and driver-offset limiter remain the frozen mechanics. CAR/BIKE differences remain profile data and presentation. HUD does not feed the solver. World pose, depth, metric, Painter order, physical gates, COMMIT continuity and recovery without progress awards remain unchanged.

Syntax comparison after removing import/format differences confirms unchanged force/control implementations and production profile values. Vehicle construction changes only its argument contract; tire implementation types become private. Surface-domain consistency and compilation checks are the intentional boundary corrections.

The existing suite retains tire boundedness/symmetry/nonpositive slip-work checks, signed wheel roots/static braking, zero-grip and single-contact cases, flat/grade/crest/recontact behavior, all nine torque envelopes, time-step refinement, physical route/checkpoint crossings and recovery without awarded progress. Historical tests tied to duplicate root call sites, milestone labels or retired metadata schemas are explicitly superseded by their owning topic documents and live causal contracts; no valid mechanics assertion is weakened.

## Remaining limits and restart

General nonadjacent road-band intersection classification is still not implemented. Strict supported-chart validation does not close that separate geometry-validation gap. New content must not be certified from vertex/fillet/envelope checks alone; intentional unfolded circuit overlap needs topology-aware classification above Core.

Per-vehicle/front-rear calibration, coast/turn oscillation acceptance, combined-input/changing-terrain acceptance and real-phone performance/input testing remain open. The local-plane protection search does not establish global monotonicity, optimality or arbitrary-terrain physical accuracy. Mechanics are frozen; these are explicit calibration/acceptance limits, not permission to introduce hidden corrections.
