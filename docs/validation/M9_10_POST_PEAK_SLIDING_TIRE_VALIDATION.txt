Status: standalone historical release evidence for the M9.10 normative tire-law and browser

1. Release scope

M9.10 deliberately changes only the post-peak tire characteristic and its DEV browser comparison:

- preserve M9.9's compiled common axle-neutral tire seed exactly:
  muRef=1.35, rhoKnee=0.74, lowSpeedRegularization=1.0,
  frontNormalizedStiffness=9.75, rearNormalizedStiffness=9.75;
- use the exact former M9.5/M9.9 TIRE 2 peak calibration for every browser choice:
  referenceFrictionMultiplier=1.2870855880077763,
  linearStiffnessMultiplier=10.3/9.75,
  pure-lateral peak start=12 deg;
- add one vehicle-owned slidingFrictionRatio scalar;
- expose SLIDE 100 / 85 / 80 / 75 / 70 % on G, direct selector buttons and HUD;
- add one stateless C1 lateral-demand-driven post-peak falloff from the retained peak to the
  selected large-angle plateau.

The post-peak scale is independent of wheel angular speed during the scalar wheel solve, so the
retained monotone implicit wheel-root structure and pure longitudinal tire behavior are preserved.

No drift mode, drift assist, target sideslip, yaw/beta feedback, tire memory, hysteresis,
vehicle-kind branch, drive-layout handling branch, roll DOF, handbrake, clutch, camera, route,
topology or renderer change is introduced. M9.7 steering and M9.9 controllable-slide acceptance
remain unchanged. Handling remains DEV_UNCALIBRATED.

5. Executable acceptance recorded by the green run

A. Retained common reference
- M9.9 compiled common tire remains exactly 1.35 / 0.74 / 1.0 / 9.75 / 9.75;
- all nine production profiles remain on one common two-station mechanics contract;
- M9.7 all-nine steering/deep-beta regressions remain green.

B. One common peak characteristic
- every M9.10 browser choice uses referenceFrictionMultiplier=1.2870855880077763;
- every choice uses linearStiffnessMultiplier=10.3/9.75;
- effective normalized initial slope remains 10.3;
- pure-lateral peak remains exactly at the former TIRE 2 12-degree target;
- SLIDE 100% exactly preserves the former no-drop TIRE 2 force behavior.

C. Stateless post-peak falloff
- lateral demand ratio rhoLat=abs(Dy)/fmax owns the post-peak observation;
- force is unchanged through peak rhoLat=1.26 for rhoKnee=0.74;
- one C1 smoothstep falls from peak to the chosen slidingFrictionRatio;
- the plateau is reached at rhoLat=1.78, approximately 16.7 degrees for the fixed browser
  reference;
- deep pure-lateral force reaches exactly 85 / 80 / 75 / 70 percent of the SLIDE 100 result.

D. Wheel-solve preservation
- pure longitudinal force is identical across every slide-ratio choice;
- the post-peak scale is independent of Omega inside one scalar wheel solve;
- representative combined-slip solves remain finite and deterministic for all five ratios;
- the existing bounded root bracket remains valid because slideScale is in (0,1].

E. Calibration / selector ownership
- one vehicle-owned calibration atomically owns reference-friction, linear-stiffness and
  sliding-friction-ratio values;
- invalid sliding ratios are rejected before mutation;
- recovery and profile reconstruction preserve the selected calibration;
- G, direct selector buttons and HUD derive from one common five-value table.

F. Architecture boundaries
- no driftMode, driftAssist or targetSideslip authority is added;
- tire constitutive logic consumes no yaw rate, betaTravel or bodyTravelDirection;
- no profile-id or drive-layout branch is added to the tire law;
- no tire memory or hysteresis is added;
- SurfaceMap, suspension, powertrain, input, steering, camera, route, topology and renderer
  boundaries remain green;
- repository source-boundary and commit-versioned Pages boot regressions remain green.
