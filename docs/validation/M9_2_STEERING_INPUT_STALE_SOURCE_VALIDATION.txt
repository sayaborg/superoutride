Reproduced input root cause:
- keyboard and touch each retained LEFT and RIGHT independently;
- their local equality rule resolved stale RIGHT + corrective LEFT as neutral;
- releasing LEFT exposed the older stale RIGHT again;
- lifecycle reset could eventually clear the symptom but did not repair ordinary source order;
- camera and vehicle physics neither caused nor owned that retained input state.

Resolved input architecture:
- InputManager owns one device-independent SteeringInputArbiter shared by keyboard and touch;
- exactly one latest non-repeat steering source is active at a time;
- a new steering press supersedes the older source instead of retaining a second direction truth;
- releasing the active source returns exactly to neutral;
- releasing or repeating a superseded source cannot restore it;
- blur, page-hide and hidden-document lifecycle paths reset the one shared authority;
- the arbiter imports no camera, vehicle, route, physics or screen authority;
- three finite vehicle actuators remain the sole response authority after canonical input.

The envelope confirms that the visible countersteer is separate from stale canonical input and
exists below tire saturation. Removing yaw preview or slowing actuator release trades away yaw
stabilization/settling rather than removing the cause. No steering gain, preview, actuator, tire,
camera or profile calibration is changed by this hotfix. A future calibration change requires an
explicit normative/profile decision; the strongest measured candidate is an explicit profile-owned
travel-direction feedback gain rather than an ad hoc camera or tire mask.
