Resolved architecture:
- keyboard aliases and touch pointers publish exact held-source press/release events into one
  device-independent input-layer arbiter;
- a rising edge receives one monotonic order observation; key-repeat for an already-held source
  does not refresh priority;
- the newest source that remains held is the sole canonical pedal request;
- releasing the winner reveals the next-newest source that remains held, so held ACCEL resumes
  after a later BRAKE tap and the inverse sequence behaves symmetrically;
- blur, page-hide and hidden-document lifecycle paths clear every source and order observation;
- InputManager consumes the arbiter result directly instead of OR-merging device pedal booleans;
- canonical DrivingInput, recorded traces and the common vehicle boundary reject simultaneous
  throttle=true/brake=true because event order cannot be reconstructed downstream;
- steering remains independently merged under the existing touch-steering priority rule;
- throttle and brake actuators remain independent finite response states, so actual values may
  briefly overlap during a request handoff through ordinary release/apply rates;
- physics owns no pedal winner, held-source map, event history, torque cut or brake override;
- the shared HUD keeps requested steering and all three actual values as graphical meters, while
  requested ACCEL is blue, requested BRAKE is red and neutral has no active pedal color.
