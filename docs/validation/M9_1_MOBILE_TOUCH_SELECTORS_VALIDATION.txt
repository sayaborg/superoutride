Resolved architecture:
- mobile course buttons are generated from BROWSER_COURSE_MODES;
- mobile vehicle buttons are generated from BROWSER_VEHICLE_PROFILES;
- HTML owns only semantic empty mounting regions and contains no duplicate choice mapping;
- course keys and course taps converge on one boot-owned URL navigation function;
- vehicle keys and vehicle taps converge on one profile-selection function in each explicit
  composition root;
- profile switching retains the existing safe-spawn reconstruction and cannot convert live
  mechanical state or manufacture route/race progress;
- touch/coarse/phone-size layout detection is one shared browser-layer function;
- the phone fallback uses viewport short side <=720 px for embedded browsers without pointer
  metadata and therefore works from either initial orientation;
- portrait and landscape selector buttons have a minimum 44x44 px hit area;
- active styling and aria-pressed are presentation state only;
- no lower renderer, physics, camera, topology, route, gameplay or DEV-fixture branch is added.
